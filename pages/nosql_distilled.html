NoSQL Distilled

Posted on April 24, 2025 | In: NotSQ

NoSQL born out of need to handle larger data volumes through cluster

  • NoSQL generally applied to
    • Non-relational databases
    • schemaless data
  • NoSQL trade off consistancy for
    • Productivity ⟶ Application development Productivity ⟶ No need mapping between in-memory data structure and relational databases (No impedance mismatch)
    • Performance ⟶ Cluster ⟶ Relational databases suitable for Single machine ⟶ NoSQL databases suitable for multiple machine (cluster) ⟶ Better for big data scenario
  • Common characteristics of the NoSQL databases
    • ✘ Not using relational model
    • ✔ Running well on clusters ⟶ Size and performance
    • ✔ Open source
    • ✔ Schemaless ⟶ No impedance mismatch
  • Relational databases
    • Consistancy ⟶ transaction
      • ✘ Relational databases use ACID transactions that inherently clashes with a cluster environment
    • Integratiokn ⟶ Shared database ⟶ multiple application, single database scenario
      • ✘ Different applications have different structure and performance needs]
        • ✔ Solution ⟶ Service-oriented architecture ⟶ Shift from integration databases to the application databases
    • Standard model ⟶ For different relational databases core mechanisms remain same
    • Impedance mismatch ⟶ Differnce between the relational model and in-memory data structure
      • ✔ Solution ⟶ ORM (Object-relational mapping) frameworks
  • Scale
    • Scale up ⟶ hardware
    • Scale out ⟶ cluster

NoSQL ⟶ ✔ Movement ✘ Technology

● Polygot persistance ⟶ NoSQL databases + Relational databases

● To make polygot persistance works ⟶ organizations also need ⟶ shift from ⟶ integration databases to the application databases(encapsulating data in services)

✘ NoSQL databases are not a good choice for integration databases.

Aggregate data model

● Data model ⟶ The model through which we perceive and manipulate data ≠ Storage data model
  • Data model
    • Aggregate ignorant ⟶ Relational
    • Aggregate oriented ⟶ NoSQL
      • Key-Value
      • Document
      • Column-Family
      • Graph (Aggregate ignorant)
  • Aggregate
    • Data manipulation ⟶ Update aggregate with atomic operations
    • Management of consistancy (transation) ⟶ Communicate with our data storage in therms of aggregate
  • Transactions
    • Relational databases ⟶ Aggregate ignorant databases ⟶ ACID transaciton ⟶ Any combination of rows
    • NoSQL databases ⟶ Aggregate oriented databases
      • ✘ Multiple aggregate ⟶ No ACID transaction
      • ✔ Single aggregate ⟶ Atomic manipulation
  • NoSQL databases (aggregate oriented)
    • Key-Value
      • Strongly aggregate oriented
      • Aggregate is opaque to the database
      • Having Key or ID to get data
