Redis

Posted on September 08, 2025 | In: Redis
  • Redis
    • In memory database ⟶ Fast
    • Non-Relational databaes (NoSQL) ⟶ key-value
    • Remote ⟶ Making it accessible to multiple client/servers
    • Persistent ⟶ The opportunity to keep data between reboots.
    • Scaleable
      • Sharding
      • Slaving
    • Support
      • Replication ⟶ Scale read performance
      • client side sharding ⟶ Scale write performance
  • Redis allow us to store keys that map to any one of five different data structur types
    • STRING
      • Content: strings, integers, floating point
        • Byte string
        • Integer (Can be incremented or decremented by an arbitrary numeric)
          • Integers turning into floats as neccessary.
          • Integers have ranges that are equivalent to the platform's long integer ⟶ In 32 bit system 32 bit ⟶ In 64 bit system 64 bit
        • Floating-point (Can be incremented or decremented by an arbitrary numeric)
          • Floats have ranges and values limited to IEEE 754 floating-point doubles.
      • Points:
      • Commands:
        • GET ⟶ Fetch the data at the given key
        • SET ⟶ Sets the value stored at the given key
        • DEL ⟶ Deletes the value stored at the given key
        • INCR ⟶ Increment the value stored at the key by 1
          • INCR* or DECR* ⟶ Key that doesn't exist, Key's value is empty string ⟶ Redis will operate as though that key's value were zero
          • INCR* or DECR* ⟶ Value can not be interpreted as an integer or float ⟶ We will receive an error.
        • DECR ⟵ Decrement the value stored at the key by 1
        • INCRBY ⟶ Increment the value stored at the key by the provided integer value
        • DECRBY ⟶ Decrement the value stored at the key by the provided integer value
        • INCRBYFLOAT ⟶ Increment the value stored at the key by the provided float value
        • APPEND ⟶ Concatenates the provided value to the string already stored at the given key
          • When reading STRINGs with GETRANGE, any request for data beyond the end of the STRING won't be returned
          • When reading bits with GETBIT, any bit beyond the end of the STRING is considered zero
        • GETRANGE ⟶ Fetches the substring, including all characters from the start offset to the end offset, inclusive
        • SETRANGE ⟶ Sets the substring starting at the provided offset to the given value
        • GETBIT ⟶ Treats the byte string as a bit string, and return the value of the bit in the string at the provided bit offset
        • SETBIT ⟶ Treats the byte string as a bit string, adn sets the value of the bit in the string at the provided bit offset
        • BITCOUNT ⟶ Counts the number of 1 bits in the string, optionally starting and finishing at the provided byte offsets
        • BITOP ⟶ Performs ne of the bitwise operations, AND, OR, XOR or NOT, on the strings provided, storing the result in the destination key
    • LIST
      • Content: linked list of strings
        • Commands:
        • RPUSH ⟶ Pushes the value onto the right end of the list
        • LRANGE ⟶ Fetches a range of values from the list
        • LINDEX ⟶ Fetches an item at a given position in the list
        • LPOP ⟶ Pops the value from the left end of the list and return it
        • RPUSH ⟶ Return the value(s) onto the right end of the list
        • LPUSH ⟶ Pushes the values(s) onto the left end of the list
        • RPOP ⟶ Remove and return the rightmost item from the list
        • LPOP ⟶ Remove and return the leftmost item from the list
        • LINDEX ⟶ Return the item at the given offest
        • LRANGE ⟶ Return the items in the list at the offests from start to end, inclusive
        • LTRIM ⟶ Trim the list to only include items at indices between start and end, inclusive
        • RPOPLPUSH ⟶ Pops the rightmost item from the source and LPUSHes the item to the destination, also returning the item to the user
        • BLPOP ⟶ Pops the leftmost item from the first non-empty LIST, or waits the timeout in seconds for an item
        • BRPOP ⟶ Pops the rightmost item from the source and LPUSHes the item to the destination, also returning the item to the user
        • BRPOPLPUSH ⟶Pops the rightmost item from the source and LPUSHes the item to the destination, also returning the item to the user, and waiting up to the timout if the source is empty
    • SET
      • Content: Unordered collection of strings
      • Points:
        • Because redis SET are unordered and unique we can not pop and push items from the ends like we did with LISTs. ⟶ instead we add or remove items by values
      • Commands:
        • SADD ⟶ Add item to the set
        • SMEMBERS ⟶ Returns the entire set of items
        • SISMEMBER ⟶ Check if an item is in the set
        • SREM ⟶ Removes the item from the set, if exists
        • SCARD ⟶ Returns whether the item is in the SET
        • SRANDMEMBERS ⟶ Return one or more random items from the SET. When count is positive, Redis will return ⟶ distinct randomly chosen items, and when ⟶ count is negative, Redis will return ⟶ randomly chosen items that may not be distinct
        • SPOP ⟶ Removes and return a random item from the SET
        • SMOVE ⟶ If the item is in the source, removes the item from the source and adds it to the destination, returning if the item was moved
        • SDIFF ⟶ Returns the items in the first SET that weren't in any of the other SETs
        • SDIFFSTORE ⟶ Stores at the dest-key the items in the first SET that weren't in any of the other SETs
        • SINTER ⟶ Returns the items that are in all f the SETs
        • SINTERSTORE ⟶ Stores at the dest-key the items that are in all of the SETs
        • SUNION ⟶ Returns the items that are in at least one of the SETs
        • SUNIONSTORE ⟶ Stores at the dest-key the itmes that are in at least one of the SETs
    • HASH
      • Content: Unordered hash table of keys to values
        • Points:
        • Miniature versions of Redis
      • Commands:
        • HSET ⟶ Stores the value at the key in the hash
        • HGET ⟶ Fetches the value at the given hash key
        • HGETALL ⟶ Fetches the entire hash
        • HDEL ⟶ Removes a key from the hash, if it exists
        • HINCRBY ⟶ Increments a value in a hash
    • ZSET
      • Content: Ordered mapping of strings to floating-point scores ⟶ ordered by score
      • Points:
        • The keys(memebers) are unique and values are limited to floating-point numbers.
        • ZSET keep items orderd by the item score ⟶ ZSETs are sorted in ascending order by their score.
      • Commands:
        • ZADD ⟶ Add member with the given score to the ZSET
        • ZRANGE ⟶ Fetch the items in the ZSET from their positions in sorted order
        • ZRANGEBYSCORE (asc), ZREVRANGEBYSCORE (desc) ⟶ Fetch items in the ZSET based on a range of scores
        • ZREM ⟶ Remove the item from the ZSET, if it exists
        • ZINCRBY ⟶ Increment the score of the member.
  • General Points
    • Seprator between parts of the names → The choice is subjective → : is common among redis users → Other options . / |
    • The ensure that SET we'll give it an expiration time with EXPIRE command, which lets Redis automatically delete it.
    • As matter of keeping the syntax of commands simple, Redis doesn't allow nested structures ⟶ If necessary, we can user key names for this → or → We can explicitly store our nested structures using JSON or some other serialization library of our choice.
    • Redis has the capability to perform operations involving multiple SETs. and → in some cases, between SETs and ZSETs.
